# 캐릭터 클릭 타입 테스트

캐릭터의 성격과 분위기를 실제 클리커 스위치의 소리와 손끝 감각으로 바꾸는 공개용 테스트입니다.
기존 축BTI의 8축 점수 계산, Q1·Q11 겉과 속 대비, Google Sheets 스위치 데이터와 질문 편집기를 유지하면서 공개 랜딩·결과 해석·공유·상품 연결을 추가했습니다.

## 실행

```bash
npm start
```

브라우저에서 `http://localhost:8080`을 엽니다. 빌드 과정이나 외부 API는 필요하지 않습니다.

자동 테스트는 다음 명령으로 실행합니다.

```bash
npm test
```

추천 1위가 37개 스위치에 얼마나 분산되는지 결정론적 응답 표본으로 확인하려면 다음 명령을 사용합니다.

```bash
npm run audit:distribution -- 100000
```

이 감사는 분포 편향을 찾기 위한 표본 검사이며 전체 `4^13` 조합의 수학적 도달 가능성 증명은 아닙니다.

## 공개 사용자 흐름

1. 테스트 소개와 소요 시간 확인
2. 선택적으로 캐릭터 이름 입력
3. 13문항 응답
4. 캐릭터 클릭 타입과 2~4문장 해석 확인
5. Q1·Q11을 연결한 겉과 속 해석 확인
6. 어울리는 클릭감과 추천 스위치 3개 확인
7. 결과 PNG 저장, Web Share 또는 결과 링크 복사
8. 설정된 경우에만 상품·제작 방식·신청 페이지로 이동
9. 이름과 답변을 초기화하고 다른 캐릭터 테스트

## 공개 설정

공개 문구, 브랜드명, URL, 자산 경로, 용어 설명, 진행 문구와 결과 유형 규칙은 모두
`src/publicConfig.js`에서 관리합니다.

현재 다음 값은 의도적으로 비어 있습니다.

- 상품 페이지 URL
- 제작 방식 URL
- 신청 일정 URL
- 신청 페이지 URL
- SNS URL
- 카카오 JavaScript 키와 템플릿 ID
- favicon과 SNS 대표 이미지

빈 URL의 버튼은 표시되지 않습니다. 임의 주소나 SDK 키는 사용하지 않습니다.

메타 문구를 수정한 뒤 다음 명령을 실행하면 크롤러가 읽는 `index.html`의 정적 메타 태그도 함께 갱신됩니다.

```bash
npm run sync:meta
```

결과별 동적 OG 이미지는 정적 사이트만으로 제공하지 않습니다. 현재는 설정된 경우 공통 대표 이미지만 사용합니다.

## 실제 이미지와 영상

다음 위치에 실제 자산을 추가할 수 있습니다.

- `public/assets/product-intro.webp`
- `public/assets/product-click.mp4`
- `public/assets/og.webp`

제품 이미지가 없으면 깨진 이미지 대신 교체 가능한 플레이스홀더가 표시됩니다. 영상은 자동으로 소리를 재생하지 않습니다.

## 결과 공유

- 결과 카드는 외부 라이브러리 없이 Canvas 1080×1920 PNG로 생성합니다.
- 시스템 한글 글꼴을 기다린 뒤 그리며 긴 문구는 카드 안에서 자동 줄바꿈합니다.
- iOS에서 파일 공유를 지원하면 기본 공유 메뉴를 열고, 그 외 환경에서는 PNG를 내려받습니다.
- 결과 링크에는 13개 답변과 공개 재추천의 타입·소음 필터를 함께 직렬화합니다.
- 기존 11문항 공유 링크는 새 Q12·Q13을 기본 B 응답으로 보완해 계속 열 수 있습니다.
- 캐릭터 이름은 공유 URL에 포함하지 않습니다.
- 잘못되거나 오래된 결과 데이터는 검증 후 무시합니다.

카카오톡 공유는 SDK 키와 템플릿이 정해지지 않아 버튼을 만들지 않았습니다. 설정 위치만 준비되어 있습니다.

## 공개 화면과 내부 화면

- 공개 테스트: `index.html`
- 질문·점수·스위치 결측 관리: `editor.html`
- 내부 점수 확인: `index.html?admin=1&debug=1`

공개 메인에는 편집기 링크와 디버그 용어를 표시하지 않습니다. 내부 화면에는 `noindex` 메타를 적용했고 진입 로직도 일반 공개 흐름과 분리했습니다.

다만 이 프로젝트는 백엔드와 인증이 없는 정적 사이트입니다. URL을 아는 사용자의 관리자 화면 접근을 실제로 막을 수는 없습니다. 공개 배포 시 호스팅 서비스의 접근 제어, 별도 관리자 빌드 또는 인증 프록시를 붙여야 합니다. 현재 구조를 보안 기능으로 오해하면 안 됩니다.

## 점수 계산

- 8축: 조용함, 무게감, 반응성, 촉각 피드백, 온도감, 선명도, 매끄러움, 존재감
- 기본 키감 일치도: 최대 80점
- Q1·Q4·Q11에서 강한 겉·대인 태도·속내 대비가 확인될 때만 최대 20점 보너스
- 반전이 없으면 보너스는 0점이며 기본 키감 일치도 순서를 그대로 유지
- 문항 전체가 아니라 분석축별 가중치를 사용해 직접 묻는 기준 문항이 해당 축의 약 75~90%를 결정
- Q1·Q11은 기본 키감 추천에는 약하게 반영하되 대비 프로필에서는 원래 답변값을 그대로 유지
- 결측 축은 기본 유사도 분모에서 제외
- 작동압·바닥압 중 하나만 있으면 남은 값으로 무게를 재가중
- 촉각 강도가 `미상`이면 스위치 타입을 보조값으로 사용
- 이름·제품 색상·연상 이미지·제품명은 추천 순위를 바꾸지 않음

공개 유형명은 `resultTypeRules`의 첫 일치 규칙을 사용합니다. 어떤 규칙에도 해당하지 않으면 8축 중 중립값 50에서 가장 멀리 떨어진 두 특성을 조합합니다. 무작위 표현은 없습니다.

## 이벤트 추적 연결

`src/analytics.js`의 `trackEvent()`는 기본적으로 no-op에 가까운 교체 지점입니다. 다음 이벤트가 준비되어 있습니다.

- `test_start`
- `question_answer`
- `test_complete`
- `result_share`
- `result_image_download`
- `product_view_click`
- `application_click`
- `retest_click`

`window.chukbtiTrack` 함수를 제공하거나 `chukbti:track` 이벤트를 수신해 원하는 분석 도구를 연결할 수 있습니다. 캐릭터 이름과 답변 원문은 이벤트 payload로 보내지 않습니다.

## 주요 파일

- `index.html`, `public.css`: 공개 테스트 화면
- `src/app.js`: 공개 사용자 흐름과 결과 렌더링
- `src/publicConfig.js`: 공개 문구·URL·유형 규칙
- `src/resultPresentation.js`: 유형명·해석·단계 표현·추가 추천 라벨
- `src/share.js`: 결과 URL·클립보드·Canvas 이미지
- `src/analytics.js`: 교체 가능한 이벤트 추적 진입점
- `editor.html`, `src/editor.js`, `styles.css`: 내부 편집·데이터 점검
- `src/scoring/engine.js`, `src/characterContrast.js`: 기본 키감 80점과 조건부 반전 보너스 20점 추천 엔진
- `tests/`: 계산 회귀와 공개 UX 데이터 테스트

## 아직 외부 자료가 필요한 항목

- 실제 제품 사진 또는 영상
- favicon과 공통 SNS 대표 이미지
- 운영 중인 상품·제작 방식·신청·SNS URL
- 카카오 SDK 키와 공유 템플릿
- 실제 분석 서비스 연결
- 배포 환경 관리자 인증
- 결과별 동적 OG 이미지를 위한 서버 기능

두 캐릭터 비교와 여러 캐릭터 결과 모아보기는 이번 범위에 포함하지 않았습니다. 대신 결과 스냅샷을 버전이 있는 재사용 가능한 객체로 생성하도록 설계했습니다.
